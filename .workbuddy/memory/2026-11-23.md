- 取证方式：仓库副本里跑全量 `make`（97 个目标 / 93 成功 / 4 失败）、`-Wall -Wextra` 扫描 152 个 `.cpp`（297 条告警）、
  可疑代码单独编译并独立进程运行。
- 关键结论：
  - 构建失败 4 处：`01.base_style` 用 MSVC 专有 `__int32_t`；`06.stl/mdspan` 缺 `<mdspan>`；
    `12.execution` 缺 `-ltbb`；`modern_book` 的 Makefile include 路径错（`../build` 应为 `../../build`）+ CMake 用 C++17。
  - 实测崩溃：链表 `delete_elem(size)` 空指针 ×2（exit 139）；`basic_any` 自赋值后 terminate（exit 3）。
  - 实测泄漏：`basic_any` 析构条件写反（`if(!ptr_)`），1000 次构造 = 1000 次未释放。
  - 实测 BMP：仓库自带 `bmp_8.bmp`(1bpp)/`bmp_16.bmp`(4bpp) 被按 1 字节/像素解码，缓冲区放大 8×/2×。
- 环境坑（可复用）：MSYS2 下 `[ -f dir/target ]` 会把不存在的 `target` 解析成 `target.exe`，
  用 `find`+`ls | grep -qx` 才能得到真实的产物分布（66 只有 target / 11 只有 .exe / 7 两者并存）。
  另：`std::result_of` 在 C++20 已从标准移除，但 libstdc++ 仍容忍，实测可编译——不能据此断言"编译不过"。
